Core Tags

<if> / <else>

Conditionally renders content or applies attribute tags.

An <if> renders when its value= attribute (shorthand used below) is truthy. An <else> may include an if= condition to chain branches, evaluated in order:

<if=EXPRESSION>Body A</if>
<else if=ANOTHER_EXPRESSION>Body B</else>
<else>Body C</else>
if=EXPRESSION -- Body A
else if=ANOTHER_EXPRESSION -- Body B
else -- Body C
Tip

<if> discards its DOM and state when hidden and rebuilds fresh state when shown again. To toggle visibility while preserving state, use <show>.

<show>

Toggles whether its content is attached to the document based on whether value= is truthy:

<show=EXPRESSION>Body</show>
show=EXPRESSION -- Body

Unlike <if>, <show> renders its content once and keeps it mounted. Toggling value= only attaches or detaches the DOM nodes, preserving tag variables, form values, and DOM state:

<let/showFilters=false>

<button onClick() { showFilters = !showFilters }>Filters</button>

<show=showFilters>
  <input type="search" name="brand" placeholder="Brand">
  <select name="condition">
    <option>New</option>
    <option>Used</option>
  </select>
</show>
let/showFilters=false

button onClick() { showFilters = !showFilters } -- Filters

show=showFilters
  input type="search" name="brand" placeholder="Brand"
  select name="condition"
    option -- New
    option -- Used

Because the content is built inline in the surrounding template, a reactive <show> ships only a small toggle helper rather than the template code to recreate its body. A statically truthy <show> compiles to plain markup with no runtime overhead.

Tip

Use <show> for content that toggles frequently, holds state worth preserving (form inputs, stateful components, or <lifecycle> widgets), or contains bulky static markup. Use <if> when hidden content should not render or appear in server HTML.

Note

Hidden content renders on the server inside a wrapper with the hidden attribute so it can resume without re-rendering; once toggled in the browser, hidden nodes are detached from the document. Because nodes leave the document, transient browser state such as focus and text selection resets on hide.

<show> requires content and accepts only value=.

<for>

Iterates over collections or numeric ranges to render content or apply attribute tags, exposing iteration values via tag parameters:

  • Arrays and iterables with of=:

    <for|item, index| of=["a", "b", "c"]>${index}: ${item}</for>
    for|item, index| of=["a", "b", "c"] -- ${index}: ${item}

  • Object entries with in=:

    <for|key, value| in={ a: 1, b: 2, c: 3 }>${key}: ${value}</for>
    for|key, value| in={ a: 1, b: 2, c: 3 } -- ${key}: ${value}

  • Exclusive numeric ranges with until=, from=, and step=:

    <for|num| until=5>${num}</for>
// 0 1 2 3 4

<for|num| from=3 until=7>${num}</for>
// 3 4 5 6

<for|num| from=2 until=10 step=2>${num}</for>
// 2 4 6 8
    for|num| until=5 -- ${num}
// 0 1 2 3 4

for|num| from=3 until=7 -- ${num}
// 3 4 5 6

for|num| from=2 until=10 step=2 -- ${num}
// 2 4 6 8

  • Inclusive numeric ranges with to=, from=, and step=:

    <for|num| to=5>${num}</for>
// 0 1 2 3 4 5

<for|num| from=3 to=7>${num}</for>
// 3 4 5 6 7

<for|num| from=2 to=10 step=2>${num}</for>
// 2 4 6 8 10
    for|num| to=5 -- ${num}
// 0 1 2 3 4 5

for|num| from=3 to=7 -- ${num}
// 3 4 5 6 7

for|num| from=2 to=10 step=2 -- ${num}
// 2 4 6 8 10

step= accepts negative or fractional values:

<for|num| from=10 to=0 step=-5>${num}</for>
// 10 5 0

<for|num| from=0 to=1 step=0.25>${num}</for>
// 0 0.25 0.5 0.75 1
for|num| from=10 to=0 step=-5 -- ${num}
// 10 5 0

for|num| from=0 to=1 step=0.25 -- ${num}
// 0 0.25 0.5 0.75 1

A nullish of= or in= renders nothing, so optional values such as repeated attribute tags can be iterated directly.

Pass by= on a content-rendering <for> to key each iteration so DOM nodes and local state persist across reorderings. by= accepts a function receiving the loop parameters, or a property name string when using of=:

<for|user| of=users by=(user) => user.id>
  ${user.firstName} ${user.lastName}
</for>

<for|user| of=users by="id">${user.firstName} ${user.lastName}</for>
for|user| of=users by=(user) => user.id -- ${user.firstName} ${user.lastName}

for|user| of=users by="id" -- ${user.firstName} ${user.lastName}

Each key must be a string or number unique within the loop.

<let>

Declares mutable reactive state through its tag variable, initialized from value=:

<let/count=1>

<button onClick() { count++ }>Current count: ${count}</button>
let/count=1

button onClick() { count++ } -- Current count: ${count}

Reassigning count updates every expression that reads it.

Note

An uncontrolled <let> uses value= only as its initial value. Subsequent changes to the initializing expression do not overwrite the variable unless the <let> is controllable.

<let/count=input.initialCount>
<p>Count: ${count}</p>
<p>Input Count: ${input.initialCount}</p>
export interface Input {
  initialCount: number;
}

<let/count=input.initialCount>
<p>Count: ${count}</p>
<p>Input Count: ${input.initialCount}</p>
let/count=input.initialCount
p -- Count: ${count}
p -- Input Count: ${input.initialCount}
export interface Input {
  initialCount: number;
}

let/count=input.initialCount
p -- Count: ${count}
p -- Input Count: ${input.initialCount}

Under TypeScript's strictNullChecks, a <let> initialized to null keeps the type null without widening; supply a type argument or assertion such as <let<string | null>/selected=null> or <let/selected=null as string | null>.

Controllable Let

Adding valueChange= makes <let> controllable, matching native tag change handlers. Writes to the tag variable invoke valueChange instead of mutating local state directly:

<let/value="HELLO">
<let/controlledValue=value
  valueChange(newValue) {
  value = newValue.toUpperCase();
}
>
let/value="HELLO"
let/controlledValue=value
  ,valueChange(newValue) {
  value = newValue.toUpperCase();
}

In components, forwarding input.count via two-way binding (<let/count:=input.count>, shorthand for <let/count=input.count valueChange=input.countChange>) lets callers choose uncontrolled or controlled mode:

tags/counter.marko
<let/count:=input.count>
<button onClick() {
  count++;
}>
  Clicked ${count} times
</button>
export interface Input {
  count: number;
  countChange?: (count: number) => void;
}

<let/count:=input.count>

<button onClick() { count++ }>Clicked ${count} times</button>
let/count:=input.count
button onClick() {
  count++;
} -- Clicked ${count} times
export interface Input {
  count: number;
  countChange?: (count: number) => void;
}

let/count:=input.count

button onClick() { count++ } -- Clicked ${count} times
index.marko
// Uncontrolled: counter manages its own state starting at 0
<counter count=0/>

// Controlled: parent owns state
<let/count=0>
<counter count:=count/>
<button onClick() { count = 0 }>Reset</button>
// Uncontrolled: counter manages its own state starting at 0
counter count=0

// Controlled: parent owns state
let/count=0
counter count:=count
button onClick() { count = 0 } -- Reset

To make count?: number optional with a default value, pass value= and valueChange= explicitly since := cannot take a fallback such as ?? 0:

<let/count=(input.count ?? 0) valueChange=input.countChange>
let/count=(input.count ?? 0) valueChange=input.countChange

<const>

Declares a reactive derived value computed from value= and exposed through its tag variable:

<let/count=1>
<const/doubleCount=count * 2>

<button onClick() { count++ }>
  Current count: ${count} And the double is ${doubleCount}
</button>
let/count=1
const/doubleCount=count * 2

button onClick() { count++ } --
  Current count: ${count} And the double is ${doubleCount}

Because updates are batched, reassigning count updates doubleCount when the queue flushes rather than synchronously inside the handler (see Stale Derived Values).

Note

<const> is initialized per component instance. For module-wide constants shared across all instances, use static const.

Tip

<const> is conceptually equivalent to a component returning input.value:

<return=input.value>
export interface Input<T> {
  value: T;
}

<return=input.value>
return=input.value
export interface Input<T> {
  value: T;
}

return=input.value

<return>

Exposes a tag variable from a custom tag via value=:

tags/answer.marko
<return=42>
return=42
index.marko

Warning

Each template or tag content body may contain at most one <return> at its top level. Express conditional return values inside value= rather than placing <return> inside <if> or <for>.

Content Return

A tag content block may also contain <return>, read via a tag variable on the tag that renders that content.

With <define>, a snippet can encapsulate state and expose it at its call site:

<define/ZoomControls>
  <let/level=1>
  <button onClick() { level = Math.max(0.5, level - 0.25) }>Zoom out</button>
  <button onClick() { level = Math.min(3, level + 0.25) }>Zoom in</button>
  <return=level>
</define>

<ZoomControls/zoom/>
<img alt="Floor plan" src="/blueprint.png" style=`scale: ${zoom}`>
define/ZoomControls
  let/level=1
  button onClick() { level = Math.max(0.5, level - 0.25) } -- Zoom out
  button onClick() { level = Math.min(3, level + 0.25) } -- Zoom in
  return=level

ZoomControls/zoom
img alt="Floor plan" src="/blueprint.png" style=`scale: ${zoom}`

<script>

Runs reactive side effects in the browser after the DOM has mounted and updated, including child tag DOM.

A <script> re-runs whenever any reactive tag variable, tag parameter, or input property read inside its body changes. Reading a DOM element getter (such as myButton()) or assigning to a <let> without reading it does not subscribe the effect.

<let/count=1>
<button/myButton onClick() { count++ }>Current count: ${count}</button>

<script>
  // Runs on mount and whenever `count` changes
  console.log("clicked", myButton(), count, "times");
</script>
let/count=1
button/myButton onClick() { count++ } -- Current count: ${count}

script
  --

    // Runs on mount and whenever `count` changes
    console.log("clicked", myButton(), count, "times");

  --

Pair <script> with $signal to clean up listeners, timers, or subscriptions before each re-run and on unmount:

<script>
  const intervalId = setInterval(() => {
    console.log("time", Date.now());
  }, 1000);

  $signal.onabort = () => clearInterval(intervalId);
</script>
script
  --

    const intervalId = setInterval(() => {
      console.log("time", Date.now());
    }, 1000);

    $signal.onabort = () => clearInterval(intervalId);

  --
Note

Execution order between separate <script> tags (and <lifecycle> hooks) is not guaranteed by source order. A <script> that reads a reactive tag variable attaches to that variable's initialization, so it can run before an earlier <script> that reads no reactive state. Additionally, reading a reactive variable anywhere inside <script> (including inside a registered event callback) subscribes the effect and aborts $signal on every change. For run-once setup that reads state in callbacks, or for paired restore-and-persist flows, use <lifecycle>.

Function Value

An effect can also be supplied via value= (written with =), receiving no arguments and re-running under the same rules:

<video/clip src=input.src controls/>

<script=() => (clip().muted = input.muted)/>
video/clip src=input.src controls

script=() => (clip().muted = input.muted)
<const/remember() {
  sessionStorage.setItem("sidebar", String(input.collapsed));
}>

<script=remember/>
const/remember() {
  sessionStorage.setItem("sidebar", String(input.collapsed));
}

Async Effects

Using await in a <script> body compiles it to an async function that runs without blocking other effects:

<img/photo>
<script>
  const signal = $signal;
  photo().src = input.src;
  await photo().decode();
  if (!signal.aborted) photo().classList.add("loaded");
</script>
img/photo
script
  --

    const signal = $signal;
    photo().src = input.src;
    await photo().decode();
    if (!signal.aborted) photo().classList.add("loaded");

  --
Warning

$signal resolves to the active run's signal, so capture it in a local variable before any await.

Tip

To emit a literal HTML <script> element instead of a Marko effect, use <html-script>.

Dynamic Values

<style> accepts ${...} interpolations in CSS declaration value positions:

<style>
  .toast {
    border-color: ${input.tone};
    animation-duration: calc(${input.delay} * 1ms);
  }
</style>

<div class="toast">Saved!</div>
style
  --

    .toast {
      border-color: ${input.tone};
      animation-duration: calc(${input.delay} * 1ms);
    }

  --

div class="toast" -- Saved!

The stylesheet remains static and extracted into the CSS bundle. Each interpolation compiles to a CSS custom property scoped via a small runtime <style> element to subsequent sibling elements and their descendants, updating only the custom property when state changes. Values are escaped so untrusted input cannot break out of the stylesheet.

Note

Place a <style> tag with dynamic values before the sibling elements it styles.

Interpolations are valid in CSS declaration values (not selectors, at-rule preludes, property names, quoted strings, unquoted url(...), or concatenated directly with adjacent tokens like ${size}px or 10${x}). Include units in the value or multiply with calc():

<style>
  .dropzone {
    /* Complete CSS value, e.g. "2px dashed teal" */
    outline: ${input.outline};
    /* Unitless number multiplied by a unit */
    outline-offset: calc(${input.offset} * 1px);
  }
</style>

<div class="dropzone">Drop files here</div>
style
  --

    .dropzone {
      /* Complete CSS value, e.g. "2px dashed teal" */
      outline: ${input.outline};
      /* Unitless number multiplied by a unit */
      outline-offset: calc(${input.offset} * 1px);
    }

  --

div class="dropzone" -- Drop files here
Tip

To emit a literal inline HTML <style> element, use <html-style>.

<lifecycle>

Synchronizes imperative browser APIs across mount, update, and destroy phases:

<lifecycle
  onMount() {
    // Runs once when attached to the DOM
  }
  onUpdate() {
    // Runs when any reactive value read by the tag's attributes changes
  }
  onDestroy() {
    // Runs once when removed from the DOM
  }
>
lifecycle
  ,onMount() {
    // Runs once when attached to the DOM
  }
  ,onUpdate() {
    // Runs when any reactive value read by the tag's attributes changes
  }
  ,onDestroy() {
    // Runs once when removed from the DOM
  }

Any reactive value read by the tag's attributes triggers onUpdate, including values read inside onMount, onDestroy, or callbacks they create. Before each onUpdate, tag attributes are reassigned onto this, keeping this consistent across the tag's lifetime so callbacks registered in onMount always read fresh values. This also fits restore-and-persist flows (restore once in onMount, persist changes in onUpdate).

client import { createEditor } from "code-editor";

<let/readOnly=false>
<div/host/>
<lifecycle
  readOnly=readOnly
  onMount() {
    const editor = createEditor(host());
    editor.on("beforeinput", (event) => {
      if (this.readOnly) event.preventDefault();
    });
    return { editor };
  }
  onUpdate() {
    this.editor.setReadOnly(this.readOnly);
  }
  onDestroy() {
    this.editor.destroy();
  }
>
client import { createEditor } from "code-editor";

let/readOnly=false
div/host
lifecycle
  ,readOnly=readOnly
  ,onMount() {
    const editor = createEditor(host());
    editor.on("beforeinput", (event) => {
      if (this.readOnly) event.preventDefault();
    });
    return { editor };
  }
  ,onUpdate() {
    this.editor.setReadOnly(this.readOnly);
  }
  ,onDestroy() {
    this.editor.destroy();
  }

  }

    this.map.destroy();
  }
>
client import { WorldMap } from "world-map-api";

<await>

Unwraps a promise from value= and passes its resolved value through a tag parameter. Non-promise values render synchronously without triggering a placeholder:

<await|user|=getUser()><img src=user.avatar>${user.name}</await>
await|user|=getUser()
  img src=user.avatar
  -- ${user.name}

When nested inside a <try> tag with @placeholder, the placeholder displays while the promise is pending:

<try>
  <div>
    <await|user|=getUser()>${user.name}</await>
  </div>

  <@placeholder>Loading...</@placeholder>
  <@catch|err|>${err.message}</@catch>
</try>
try
  div
    await|user|=getUser() -- ${user.name}

  @placeholder -- Loading...
  @catch|err| -- ${err.message}

<try>

Defines error and async boundaries around its content. Accepts @catch and @placeholder attribute tags; at least one must be provided.

@catch

Catches errors thrown while rendering the <try> content or its @placeholder, including rejected <await> promises and failed lazy-loaded tag fetches. The thrown error is passed as the @catch tag parameter:

<try>
  <const/data=JSON.parse(input.rawJson)>
  <p>${data.title}</p>

  <@catch|err|>
    <p>Invalid data: ${err.message}</p>
  </@catch>
</try>
try
  const/data=JSON.parse(input.rawJson)
  p -- ${data.title}

  @catch|err|
    p -- Invalid data: ${err.message}

Errors thrown inside event handlers, <script> bodies, or <lifecycle> hooks occur outside the render path and propagate to the standard window error handler rather than @catch.

@placeholder

Displays fallback content while any nested <await> promise is pending, or while a lazily loaded tag is waiting for its trigger or loading its bundle in the browser.

<html-comment>

Outputs a literal HTML <!-- comment --> (standard comments are stripped). Interpolations inside <html-comment> escape > to >:

<html-comment>Hello, view source</html-comment>
html-comment -- Hello, view source

Exposes a tag variable getter returning the DOM Comment node:

<html-comment/commentNode/>

<return() {
  return commentNode().parentElement?.getBoundingClientRect();
}>
html-comment/commentNode

return() {
  return commentNode().parentElement?.getBoundingClientRect();
}

<html-script> & <html-style>

Marko's <script> and <style> tags provide reactive browser effects and bundled CSS. When a literal HTML <script> or <style> element is required (such as an import map or inline JSON data), use <html-script> and <html-style>:

// Emits a literal HTML `<script>` element
<html-script type="importmap">
  { "imports": { "square": "./module/shapes/square.js" } }
</html-script>

// Emits a literal HTML `<style>` element
<html-style>
  @import url("https://fonts.googleapis.com/css2?family=Ubuntu&display=swap");
</html-style>
// Emits a literal HTML `<script>` element
html-script type="importmap"
  --

    { "imports": { "square": "./module/shapes/square.js" } }

  --

// Emits a literal HTML `<style>` element
html-style
  --

    @import url("https://fonts.googleapis.com/css2?family=Ubuntu&display=swap");

  --
Caution

Contents of <html-script> and <html-style> execute as code, and interpolations escape only enough to avoid closing the element, so untrusted values expose the page to XSS. Never interpolate user-provided content into them.

Inside <svg> or <math>, these tags parse as markup rather than raw text, so an interpolated < opens a real element. Never nest them in SVG or MathML with user-provided content.
